# Decisions

- Open source, delivered as a Python library (for developers) plus a web app (for non-technical journalists), because the target users range from devs to laypeople.
- Store data in Postgres (hosted) / DuckDB (local) rather than Neo4j, because the anonymity metrics are custom Python anyway, entity resolution is tabular, and it's simpler for others to deploy.
- Compute graph metrics in Python (networkx/igraph) on per-licensee N-hop subgraphs, because the metrics are local to each licensee; Neo4j may be added later only as an optional export.
- Use Splink for entity resolution, because it runs directly on DuckDB/Postgres tables.
- Render the web graph view with Cytoscape.js, so laypeople never interact with a database.
- Start with US sources (FCC ULS, Form 602, a state registry, OpenCorporates) plus GLEIF early, because FCC licensees are the investigation's starting point and GLEIF has clean, free parent-relationship data; ICIJ and other national registries come later toward the US + international end goal.
- MVP search by licensee name/FRN and by person name; a "most suspicious licensees" ranking is deferred as a later feature.
- Self-hosted only for now (one-command Docker setup), to avoid hosting cost and publisher liability; a public site (e.g. GitHub Pages) may come later.
- Show all inferred links (including people) with a confidence score and full evidence trail, with an optional user-set confidence threshold as a search filter, because investigators need complete access to every piece of evidence.
- Build order: data model + ground-truth cases → metrics → FCC ingestion → GLEIF/OpenCorporates + entity resolution → library API → web app/Docker/setup guide → later sources and features, so metrics are validated before real data arrives.
- Expand ground truth beyond Azerfon and U.S. Cellular by finding more documented cases, because validation depends on it.
- Keep decisions.md and methodology.md in the same one-bullet format; as of 2026-10-20 they are no longer gitignored (user's choice), along with plan.md.
- Compute owner probabilities (pᵢ) with an absorbing Markov chain over equity × edge confidence, with an explicit "unknown owner" endpoint, because it unifies documented and inferred edges and all metrics; show it alongside a documented-only equity-multiplication view (its special case) since that is legally defensible.
- Keep Bayesian/prior-based judgments (PEPs, secrecy jurisdictions) out of pᵢ and use them later as a separate red-flag overlay, so subjective weights stay visible and don't bias the probabilities.
- Use our own schema borrowing BODS concepts (control types, ranges, dates, per-statement sources), with BODS export later, because we need full control and telecom fields but shouldn't repeat edge-case mistakes standards already solved.
- Guiding principle: present evidence, don't conclude; make no hidden modeling decisions, and state every one publicly in the README and website, because users (journalists) should judge the evidence themselves and government standards may be shaped in governments' favor.
- Store reported ownership ranges as ranges (e.g. 25–50%), not a single number, so no precision is invented.
- When sources disagree, keep every value with its own source rather than picking one, so the user sees the conflict.
- Treat control without equity (e.g. board seats at 0%) as a real connection to the company, because untracked cash flow or influence may exist.
- Store start and end dates on each ownership/control link (e.g. 2015–2019), so past and present structures stay distinct.
- Never merge records: keep e.g. "John Smith" and "J. Smith" as separate records tied by a "possibly same" link with its evidence, so the user decides whether they're the same.
- Run metrics at both ends of every range and report result ranges, with an optional, clearly labeled midpoint mode for users who want a simpler but less exact view.
- Treat disagreeing source values as a range spanning all reported values, each shown with its source, so users can spot and exclude a bad source.
- Compute separate equity and control graphs (no invented weight for control), and annotate the equity graph where someone has a control link but 0% equity, so that link stays visible.
- Distinguish "ongoing" from "unknown" end dates, keep each date's precision (e.g. year only), and store both filing and effective dates, so time-based results can honestly say "possibly active."
- Write a public ASSUMPTIONS.md at the end, built from decisions.md, so every modeling choice is publicly stated.
- Show the most likely "possibly same" match first, with all ranked candidates and evidence in a dropdown, so casual users get a quick answer without losing access to the evidence.
- Explain every match score as a breakdown of what each piece of evidence adds or subtracts (Splink match weights), so the ranking is never a black box.
- Use transliteration-aware name comparison and weight names by how common they are, and document remaining bias risk, because transliterated and common names can systematically over- or under-match.
- Show evidence against a match as well as evidence for it, so "most likely" doesn't look stronger than it is.
- Always label unreviewed matches "Possible match, unverified," because results get screenshotted.
- Rank candidates and keep raw scores in the dropdown rather than headlining percentages, because match scores aren't reliable percentages.
- Show metrics both as "documented + your confirmations" and "including unverified top matches," with a toggle to hide the unverified set, so unreviewed matches never silently affect results.
- Export an audit trail of every user confirmation or rejection with note and timestamp, so journalists can show editors or lawyers exactly what they decided.
- Score timing gaps as percentiles against a user-chosen comparison group (e.g. same auction, license type, year), for both pair timing (two entities' events close together) and lead time (an entity's event just before an outside event such as an auction deadline), because "close in time" means nothing without knowing what's normal.
- Include small comparison groups but show their size and warn that they're small, so users can judge reliability themselves.
- State that baseline groups may themselves contain shell companies, so percentiles aren't read as comparisons against a clean population.
- Measure only event types in the data being ingested (license application and grant, transfer/assignment-of-control applications, Form 602 filings, LEI registration and GLEIF entity creation dates; FRN registration if public), leaving incorporation dates and officer changes for when state registries are added, because those aren't in FCC or GLEIF data.
- Evaluate with all three tests together: held-out case-study reconstruction, planted structures in a separate marked copy of the data, and negative controls (large and small legitimate carriers), because each covers the others' weaknesses.
- Evaluate entity matching separately on a hand-labeled sample of match pairs, so match accuracy is measured, not assumed.
- Deadline is the first week of December 2026 (paper due, plus whatever part of the tool exists); prioritize doing it well over doing it fast, because the professor values good work presented well over a rushed finished tool.
- Don't build AI/ML into the tool beyond Splink for now (LLM extraction and graph ML could come later), because of the time limit, the need for explainability, and the lack of labeled data.
- For ground truth, AI only finds candidate cases, primary documents and exact quotes; the user verifies every ownership hop against the primary document before it counts, and AI use is disclosed in the paper, because AI can fabricate citations and ground truth is what every result is measured against.
- Make ground_truth/ public in the repo, so others can reproduce the evaluation.
- Keep a plan.md with weekly assignments, for scheduling.
- (Tentative, revisit) Treat records sharing an FCC FRN or a GLEIF LEI as one entity, flagging conflicting details as possible ID errors and keeping every record splittable, because same-registry IDs are reliable and this avoids hundreds of duplicate nodes; different FRNs/LEIs stay separate, connected only by evidence-backed links.
- (Tentative, revisit) Model name and owner changes under one ID with dated attributes and edges, and treat GLEIF duplicate/successor LEI records as documented links rather than merges.
- Count directors and officers as control links, stored with their exact title as written plus a classification label (e.g. "Assistant Secretary (officer)"), because they make decisions for the company and the user should see the actual role.
- Don't count registered agents or legal counsel as control; track them as shared-attribute evidence for inferred links, weighted by how many companies share them, because they serve many unrelated companies but can also front for hidden owners.
- Store sensitive personal fields (residential address, birth date/year, personal phone/email) only as keyed hashes (HMAC), showing "same X" plus a link to the public source record but never the value, so the tool doesn't hand anyone a path to a person; business info (registered office, company phone) is shown normally.
- Standardize addresses and dates before hashing, and hash at several levels (full address, ZIP, city), because hashes only match exactly; accept some missed matches as the cost.
- Generate a random HMAC key per installation, stored separately from the database, so a stolen database or the public code can't be used to reverse hashes; state in the threat model that an instance's administrator could still brute-force them.
- Write a short threat model (adversaries, what's protected, what isn't) and state in the paper and ASSUMPTIONS.md that the open method can be used by adversaries too, because that limit should be stated honestly.
- Throw away original sensitive values after hashing (re-download from the fingerprinted source if re-processing is needed), because data we don't keep can't leak.
- No search history, click tracking or web-server access logs; store only what the user deliberately saves (match decisions and notes), locally and encrypted, because a journalist's activity reveals who they're investigating.
- Prefer bulk downloads over per-entity live lookups, and warn users before any live lookup, because querying an outside service about one target leaves a trail on their servers.
- Keep local copies of every downloaded source file, with its URL and fingerprint, because URLs break and evidence must stay verifiable.
- Commit no source documents for now, to play it safe legally; later, for reproducibility, consider committing official public-domain US government documents (not third-party copies, copyrighted material, or raw bulk data with personal info).
- Commit ground_truth/ notes (claims, quotes, citations, allegations labeled as allegations) but never the source documents themselves, because notes with citations are safe while document copies aren't yet.
- Keep every data download as a dated snapshot; always keep the snapshots used in the paper and let users choose how many others to keep (e.g. the last 4), because results must be reproducible against the exact data version.
- Store source-document copies in ground_truth/sources/ and bulk downloads in data/, both gitignored, so documents can't be committed by accident.
- Entity types are company, person, government/state body, "unknown owner" (per-company unaccounted share, never shown as a real party), and unclassified (when a source doesn't say), because forcing a guess would be a hidden decision; state-owned companies and trusts are companies with a label, and licenses are stored separately.
- License the project under AGPL-3.0 with no CLA or DCO, because anyone who modifies it (even to run as a website) must publish their changes, and keeping it simple avoids contributor friction and any hint of future proprietary relicensing.
- Name the tool/package `teleownermap`, a short name separate from the long repo name (avoiding "Tor"/"onion" for trademark reasons).
- Send a company's unaccounted ownership to "unknown owner," except for publicly traded companies, where it's labeled "public shareholders," because dispersed public ownership isn't concealment.
- When owners' shares sum to more than 100%, scale them down proportionally and flag the company, so results still compute while the inconsistency stays visible.
- Report true lower and upper bounds of each metric over all share ranges (searched numerically), not just the all-minimum vs all-maximum scenarios, because entropy can peak in the middle of a range; revisit if it becomes too slow.
- Count each company's unknown owner as a separate endpoint in entropy, and also report entropy over known owners only, because several unknowns might be the same hidden party.
- Send the unconfident part of an inferred link (share × (1 − confidence)) to "unknown owner," so uncertainty about a link becomes visible unaccounted ownership.
- Analyze the control graph as unweighted reachability (who, how many hops) with no entropy, because control links have no weights to base probabilities on.
- Treat an unstated share as the full range 0–100%, so no precision is invented.
- When sources disagree on a link's confidence, use the highest (a documented source makes the link documented), and record the disagreement in the results, so the discrepancy stays visible.
- Treat unclassified parties (e.g. "Government Official A") as ultimate endpoints, like people.
- Run a GitHub Actions lint check (ruff) on every push and pull request, to keep code style consistent.
- Add two statement labels, "admitted" (e.g. a DOJ statement of facts the company admitted) and "settled finding" (e.g. SEC findings the company neither admitted nor denied), alongside stated/alleged/found, because settlement documents fit none of the original three.
- Add a "nominee for" link type (registered party acts for a hidden party), and let nominees pass ownership and control through to that party instead of ending the chain, with any unconfident remainder staying with the nominee, because otherwise the tool would stop at the proxy and the concealment would succeed.
- Ship a complete, step-by-step setup guide for non-technical users in the repo, because self-hosting must be usable by journalists without tech expertise.
- Label P3's rows 1–4 and 7–9 "stated" and rows 5, 6 and 10 "alleged," because ¶ 37 and the MariTEL Form 602 report disclosed facts while the DePriest control claims are hearing-order allegations.
- Label P2 rows 9–11 (King Street, from D1) "alleged," because D1 recites the complaint's paragraphs rather than finding them.
- Approve `docs/data_model.md` as drafted.
- Hold out P1, P2 and P10–P12 until final evaluation and develop on P3, P4 and P6–P9, keeping cases that share entities (DiNardo/U.S. Cellular; Takilant) on the same side so tuning can't leak their answers.
- Drop TDS from the negative controls, because it owns U.S. Cellular (held-out P1/P2) and using it during development could leak their structure.
- Store the negative-control answer key as a CSV (`ground_truth/negative_controls.csv`), because it's easy for the user to edit in a spreadsheet.
- Add P5 (Gabelli) to the development cases, because it shares no entities with the held-out cases.
- Leave Azercell out of the evaluation for now, because its hidden-owner hop has no primary source to score against and it shares Telia with held-out P11.
- Store each hand-built case graph as a CSV of links in `ground_truth/graphs/` (with share range, link type, status label and the cases.md row it came from), loaded into DuckDB, so the user can check it in a spreadsheet and the real schema gets exercised.
- Build two views per case, "as disclosed" (company's own filings and publications) and "full ground truth" (plus hidden links from court/FCC documents), because the gap between them is the main result.
- Keep legal status (stated/alleged/found/admitted/settled finding) as a filter label rather than a confidence number, so no probability is invented for allegations.
- Analyze each case at a single snapshot date (its key event) and include only links valid then, deferring change-over-time analysis to future work.
- Look for control links anywhere along a licensee's ownership chain, not just on the licensee itself, so a party controlling a parent company higher up (e.g. SASAC in P7) is reported.
- Accept the hand-built graph judgment calls as drafted (disclosed/hidden split, "found" for P4's de facto control, collapsed "indirect" links, P6's UK parent not walked, P9's diagram figure, unsourced publicly-traded flags pending verification, approximate snapshot dates, five P5 bidders, "disclosed" as a CSV-only column for now).
- Don't flag a controller as "control without equity" when its own equity owners hold equity in the licensee's ownership chain (nominee arrangements don't count), so ordinary general partners owned by the limited partner aren't false positives.
- Show timing evidence primarily for pairs already linked by other evidence (shared address, agent, possible match), with an option to also show unlinked pairs labeled as possibly close by chance, because comparing every pair guarantees chance hits.
- Show timing as evidence only, not as an input to match scores or ownership metrics, because its baselines are confounded and no evaluation test measures whether it helps.
- Record event dates during FCC/GLEIF ingestion but build only the simple evidence display before the December deadline, with no timing scoring model.
- Draw paper figures with matplotlib, because it installs with pip alone (no system Graphviz), gives full layout control, and will match the results charts.
- Show only table names, primary keys and links in the schema figure, so it stays readable at paper width; full columns stay in `docs/data_model.md`.
- Generate the schema figure by reading the live DuckDB schema from `schema.py`, so the figure can't drift from the code.
- Ingest FCC ULS `owner.zip` (Form 602 and Form 175) plus the market-based, cellular, paging and coast license and application files, skipping microwave, amateur, GMRS, ship, aircraft and private land mobile, because these cover every development case and the carrier negative controls while the rest add bulk and personal data with little ownership value; the gap goes in Limitations.
- Download Form 602/175 exhibit PDFs with a rate-limited (1 request/second), self-identifying crawler that stops at the first sign of blocking, extract their text without AI, and show it only as searchable evidence passages (never as ownership links), flagging any exhibit not fetched or read; built after structured ingestion and included in the tool's update command, because the bulk file lists exhibits but omits them, and they hold the upper ownership layers (e.g. AT&T's Ex. A naming NTT's ~61% of DoCoMo); wireless2.fcc.gov's robots.txt only disallows PiplBot.
- Shelve the exhibit crawler and use user-initiated downloads instead (the user saves a filing's exhibits from the ULS site in their own browser; the tool extracts their text and flags exhibits not yet read), because FCC's firewall refuses every self-identified bot request to wireless2.fcc.gov, even robots.txt, and we won't disguise the crawler as a browser; FCC's bulk server and GLEIF accept the honest label.
- Guide users to exhibits rather than limiting search to what they've downloaded: list every exhibit from the bulk file with read/unread status, rank ownership-related titles first, point from unaccounted ownership to unread exhibits that may explain it, give step-by-step download instructions with a direct ULS link (after the live-lookup warning), and import each file through an "add" action next to that specific exhibit, because ULS saves every attachment under a generic name (e.g. "attachmentViewRD") that can't be matched automatically.
- Treat every address attached to a person in FCC filings as sensitive (hashed, never shown) and show company addresses normally, because the data doesn't say which addresses are residential and guessing would be a hidden judgment that could expose a home.
- Keep downloaded source files unaltered in gitignored `data/` but keep plain sensitive values out of the database, revising "throw away original sensitive values," because FCC overwrites its weekly files so deleted snapshots (including the paper's) could never be rebuilt; the threat model states the originals hold what FCC published.
- Show user-imported exhibit text in full but exclude it from exports and shared outputs by default, because free text can contain home addresses that can't be hashed field by field.
- Load all of GLEIF into raw staging tables but create entities only for GLEIF companies connected to an FCC entity (a possible match plus its full parent chain), because filtering by country would drop the foreign parents we're looking for, and unconnected companies can't affect any licensee's results.
- Store GLEIF "consolidated by" links as control links, adding an equity link only when GLEIF gives a percentage, and use "ultimately consolidated by" (which skips middle layers) as a cross-check rather than in the equity math, because consolidation means accounting control, not a stated ownership share, and the ultimate link would double-count the direct chain.
- Count GLEIF "fund-managed by" as control, and store sub-fund, feeder and international-branch links as shown-only evidence outside the metrics, because they describe legal or fund structure rather than ownership.
- Store GLEIF reporting exceptions (natural persons, no LEI, non-public, opt-out reasons) as sourced statements shown word for word beside the company's unaccounted share, never changing the metrics, because they are evidence for the journalist and belong with the later red-flag overlay.
- Use GLEIF's consolidation percentage as the equity share, labeled "GLEIF consolidation percentage; GLEIF doesn't define it as equity" and listed in ASSUMPTIONS.md, because in group accounts it normally is the parent's ownership interest, while the RR-CDF 2.1 schema defines it only as a percentage measured by accounting consolidation.
- Confirm (no longer tentative) that records sharing one FCC FRN or GLEIF LEI are one entity, splittable and with conflicts flagged, while a company's different FRNs are linked only by evidence-backed "possibly same" links, because one FRN can appear on over a thousand Form 602 rows and separate copies of one company would be useless.
- Store a filing's law firm as a `legal_counsel` link and its contact person as a `filing_author` link (evidence only, weighted by how many filers share them), showing their phone and email normally, because they are published professional contact details, not personal information.
- Extract exhibit text with PyMuPDF rather than pdftotext, because it handles complex official layouts comparably, installs with pip alone (the pdftotext wrapper needs a compiler and Poppler headers), and is AGPL-3.0 like this project.
- Label each downloaded file with its publisher's date and also record a named "snapshot set" per update run (e.g. FCC's Saturday application files plus Sunday license files), so the paper can cite one snapshot that pins exactly which files were used.
- Treat Form 602 `pct_interest` as an ownership (equity) percentage, because the Form 602 instructions (Item 7) call it "the ownership percentage."
- Build the equity graph only from direct Form 602 holders and show indirect holders as "named upstream parties" (reported share is an upper bound), highlighting any the graph doesn't reach and pointing to the exhibit that may explain the chain, because FCC's rule reports any link over 50% or controlling as 100% and lists each level of one stake separately, so adding indirect rows as owners would inflate and double-count.
- Decide whether a Form 602 holder is a person from which name field the filer used (Item 1 individual vs Item 2 entity), keeping the undocumented `type_entity` code as written and using `unclassified` when neither is filled, because the code list doesn't define those codes and guessing would be hidden.
- Include Form 602 filings whose `filing_type` is "P" rather than "C" (codes undefined in FCC's code list), labeled with the raw filing type and status, so nothing is silently dropped.
- Treat a direct Form 602 holder's 0.00% as unstated (0–100%), noted "reported 0.00," because a direct ownership interest of zero is contradictory and most likely a blank field.
- Treat Form 602 F/H records (other FCC-regulated businesses held, with a percentage) like indirect holders: named holdings with an upper-bound share, kept out of the equity math but used to connect licensees that share owners, because they don't say whether a holding is direct or indirect.
- Store a filing's certifier as `filing_author` with the title as written, not as a control link, because titles can belong to counsel or agents and officers are already listed as interest holders.
- Hash a person's street, address line 2, city and ZIP, and show state and country, because a name plus a city can locate a person.
- Keep the HMAC key in `~/.config/teleownermap/hmac.key` (user-only permissions, created on first run), outside `data/` and the database, so a copied database or data folder doesn't carry the key; losing it means rebuilding the database from snapshots.
- Standardize addresses locally before hashing (uppercase, no punctuation, USPS street-suffix abbreviations, 5-digit ZIP), with no outside address service, so no lookups leave the machine.
- When an FRN is typed differently across Form 602 records (e.g. a company's FRN reused for one of its officers), use the type from the FRN holder's own filing, keeping the conflict flag and the other record splittable, because the holder describing itself is the best evidence and `unclassified` would wrongly end the ownership walk at a real company.
- Type Form 602/175 parties with `type_entity` code "b" as `government`, because the user confirmed on the City of Bastrop's ULS filing that code b is displayed as "Government Entity"; other codes stay raw labels until checked the same way, so a government licensee with no owners isn't shown as concealed.
- Treat a blank country as US when hashing FCC addresses, because FCC leaves it blank for domestic addresses.
- Hash company addresses as well as people's (companies' are still shown in plain text), so "same address" can link a person to a company.
- Load the ULS license and application record types HD, EN, AD, MK, LO (locations) and HS (license history) and skip frequencies, antennas and other technical tables, because these hold the licensee, dates, transfers, markets and sites; HS gives transfer dates (`LITRAN`, `LIASS`, `LIPASS`), and TA (transfer/assignment, with consent and consummation dates) comes from `a_aatc.zip`, the only file that has it; EN "Owner" rows are kept as records only, because on all 71,941 licenses that have one they repeat the licensee's name.
- Download and load `a_aatc.zip` (assignments and transfers of control, 1987–2026), including its TA records with FCC consent and consummation dates, because transfers aren't in the per-service application files and this is the main source of who took control of whom and when.
- Load every transfer and assignment in `a_aatc.zip` regardless of radio service, stated in ASSUMPTIONS.md as the one exception to the four-service scope, because a transfer of control concerns the companies, and filtering by service could drop the transfer that reveals who took over a carrier.
- Type ULS entities from FCC's documented Applicant Type Code: Individual → person; Governmental and Tribal Entity → government; corporations, partnerships, LLCs, consortia, trusts, associations, joint ventures and business-controlled tribal entities → company with the FCC type as a label; Other or blank → unclassified.
- Never store the race, ethnicity and sex fields in ULS license and transfer records, not even hashed, and remove them from raw records, because they have no use in ownership analysis and are highly sensitive.
- Hash individual licensees' phone and email like home addresses, showing companies' normally.
- Store licensees' own answers on foreign ownership (alien, alien government, alien corporation, alien officer, alien control) and on revocation and convictions as stated attributes shown as evidence, outside the metrics.
- Store ULS license contacts as `license_contact` links (evidence only, details shown), matching Form 602 contacts.
- Record events for license grant, expiry and cancellation, application receipt by purpose (transfer of control and assignment as their own types), and license history events (issued, transferred, assigned, renewed, canceled, expired), and FCC consent and consummation dates of transfers and assignments.
- Load the application files in full, because unlike owner.zip they keep historical applications, including past transfers of control.
- Treat shared transmitter sites as evidence weighted by how many licensees share the site, flagging registered towers and ignoring a licensee's own sites, and hash an individual licensee's site address and coordinates, because tower sharing is routine and a small licensee's site can be their home; match sites by coordinates rather than address text.
- Word a licensee with no ownership filing as "no ownership filing found" rather than as unaccounted ownership, so missing filings aren't read as concealment.
- Identify downloads with the User-Agent "teleownermap" alone (no URL or email) for now, because it honestly says the request comes from a tool, and a contact isn't required.
- When FCC's bulk server refuses the tool's Python downloads (first seen 2026-10-29, while curl with the same label was accepted), first wait and retry later; if it still refuses, the user decides then whether to try curl as the download client; otherwise fall back to guided manual download in the browser plus an import command, because we stop at refusals rather than work around them unilaterally.
- Try curl as the download client for FCC bulk files, keeping the honest "teleownermap" label and stopping on any refusal, because Python's requests were still refused on 2026-10-30 while curl with the same label was accepted; the switch and its reason are recorded in the methodology log.
- Target laptops with 8 GB of RAM and about 20 GB of free disk (to be confirmed after the full load): by default DuckDB is capped at 1 GB and 4 threads and rows are inserted in 50k batches (about 2.3 GB peak on the largest FCC file), with a slower `--low-memory` option for 4 GB machines, and the requirement stated in the setup guide, because journalists run this on ordinary laptops.
- Store downloads as `data/snapshots/<source>/<publisher date>/<file>` with a JSON metadata record beside each file, so every file's URL, fingerprint and retrieval time sit next to it.
- Keep links from lapsed LEIs, labeled "LEI lapsed; data last updated <date>," so stale data is visible rather than silently used or dropped.
- For now, let the first source loaded set an FRN's entity type, loading FCC license files first (documented Applicant Type Codes) and Form 602 last, and revisit cross-source type conflicts in week 5 with entity matching.
- Map GLEIF entity categories to entity types: GENERAL → company; FUND → company labeled fund; BRANCH → company labeled branch; SOLE_PROPRIETOR → person; RESIDENT_GOVERNMENT_ENTITY and INTERNATIONAL_ORGANIZATION → government.
- Hash sole proprietors' GLEIF street, city and postal code like any person's address, including in the raw GLEIF staging tables, so the database never holds a person's plain address.
- Keep a subset of GLEIF's 338 LEI columns in staging (identifier, names, legal and headquarters addresses, jurisdiction, category, legal form, statuses, key dates, managing LOU, successor LEIs, legal-entity events), leaving the original zip untouched, and revisit the choice in week 5.
